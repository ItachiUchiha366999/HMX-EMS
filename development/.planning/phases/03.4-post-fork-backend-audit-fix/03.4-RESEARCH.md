## Architecture Patterns

### Pattern 1: Education Filter (D-02) — three API forms

```python
# Form A: frappe.get_all
docs = frappe.get_all(
    "DocType",
    filters={"module": ["in", UNIVERSITY_MODULES]},  # implicit Education exclusion
    fields=["name", "module"],
)

# Form B: explicit "not equal" when scanning all DocTypes
docs = frappe.get_all(
    "DocType",
    filters={"module": ["!=", "Education"]},
    fields=["name", "module"],
)

# Form C: raw SQL parameterized
rows = frappe.db.sql(
    """SELECT name, module FROM `tabDocType`
       WHERE module IN %(mods)s AND module != 'Education'""",
    {"mods": tuple(UNIVERSITY_MODULES)},
    as_dict=True,
)

# Form D: meta-level (rare; for workflow doctype filtering)
meta = frappe.get_meta(doctype_name)
if meta.module == "Education":
    continue  # skip
```

**Recommendation:** Prefer Form A (`module IN UNIVERSITY_MODULES`) — it implicitly excludes Education and is whitelisting (safer than Form B blacklisting).

### Pattern 2: Workspace Consistency (D-06) — NEW

The failure mode from Phase 03.3.1: 39 forked doctypes had `Card Break` rows in `tabWorkspace Link` but no matching `card_name` entry inside `Workspace.content` JSON. They rendered invisible in Desk.

```python
import json
import frappe

def audit_workspace_consistency():
    """For every public workspace, diff content JSON cards vs tabWorkspace Link Card Breaks."""
    findings = []
    workspaces = frappe.get_all(
        "Workspace",
        filters={"public": 1, "module": ["in", UNIVERSITY_MODULES]},
        fields=["name", "module", "title", "content"],
    )
    for ws in workspaces:
        # Parse content JSON -- it's a list of layout blocks
        try:
            content = json.loads(ws["content"] or "[]")
        except (TypeError, json.JSONDecodeError):
            findings.append({"workspace": ws["name"], "issue": "Invalid content JSON"})
            continue

        # Extract card_name values from blocks of type 'card'
        content_cards = {
            block.get("data", {}).get("card_name")
            for block in content
            if isinstance(block, dict) and block.get("type") == "card"
        }
        content_cards.discard(None)

        # Get all Card Break labels from tabWorkspace Link
        link_cards = set(
            row["label"]
            for row in frappe.get_all(
                "Workspace Link",
                filters={"parent": ws["name"], "type": "Card Break"},
                fields=["label"],
            )
        )

        missing_in_content = link_cards - content_cards
        orphan_in_content = content_cards - link_cards

        if missing_in_content or orphan_in_content:
            findings.append({
                "workspace": ws["name"],
                "module": ws["module"],
                "missing_in_content": sorted(missing_in_content),
                "orphan_in_content": sorted(orphan_in_content),
            })
    return findings
```

**Schema reference (verified):**
- `tabWorkspace.content` = JSON string, list of `{type, data}` blocks. `type='card'` blocks carry `data.card_name`.
- `tabWorkspace Link` rows with `type='Card Break'` use the `label` column as the card identifier.
- `tabWorkspace Link` rows with `type='Link'` are the actual desk links under each Card Break.

### Pattern 3: Workflow E2E Walker (D-05) — NEW

```python
import frappe
from frappe.model.workflow import apply_workflow, get_transitions

def walk_workflow(workflow_name):
    """Create test doc, walk every transition, verify final state, delete."""
    wf = frappe.get_doc("Workflow", workflow_name)
    doctype = wf.document_type
    state_field = wf.workflow_state_field  # default "workflow_state"

    # Build minimal valid test doc -- caller must supply a fixture factory
    doc = _create_test_doc_for(doctype)  # plan-specific helper

    visited_states = [doc.get(state_field)]
    transition_log = []
    try:
        # Walk transitions breadth-first; track unique state transitions covered
        max_steps = 20  # safety
        for _ in range(max_steps):
            transitions = get_transitions(doc)
            if not transitions:
                break
            # Pick first allowed action (or iterate all in separate test runs)
            action = transitions[0]["action"]
            apply_workflow(doc, action)
            visited_states.append(doc.get(state_field))
            transition_log.append(action)
        return {
            "workflow": workflow_name,
            "status": "PASS",
            "visited": visited_states,
            "transitions": transition_log,
        }
    except Exception as e:
        return {
            "workflow": workflow_name,
            "status": "FAIL",
            "visited": visited_states,
            "transitions": transition_log,
            "error": str(e)[:200],
        }
    finally:
        # Cleanup: hard delete to avoid workflow-block on submitted docs
        try:
            frappe.delete_doc(doctype, doc.name, force=1, ignore_permissions=True)
        except Exception:
            pass
```

**Notes:**
- `apply_workflow` lives at `frappe/model/workflow.py:99`. It mutates `doc[workflow_state_field]`, runs `doc.save()` (or `doc.submit()` if next state has `doc_status=1`), and triggers role/permission checks.
- `get_transitions(doc)` returns `[{action, state, next_state, allowed, ...}]` — only those whose `allowed` role the current `frappe.session.user` has. **Run as Administrator** to see all transitions.
- For workflows requiring child rows (e.g. Hostel Allocation needs Student + Hostel Room), the test-doc factory must seed FK fixtures or rely on demo data from plan 01.
- **For comprehensive coverage (not just first action)**, walk per-action via DFS:
  ```python
  def walk_all_paths(doc, state_field, visited_paths, current_path=()):
      transitions = get_transitions(doc)
      if not transitions:
          visited_paths.add(current_path); return
      for t in transitions:
          doc_copy = frappe.copy_doc(doc); doc_copy.insert()
          apply_workflow(doc_copy, t["action"])
          walk_all_paths(doc_copy, state_field, visited_paths, current_path + (t["action"],))
          frappe.delete_doc(doc.doctype, doc_copy.name, force=1)
  ```
  P1 simplification: just walk the happy path (first action at each step). 16 workflows × ~3-5 transitions = manageable.

### Pattern 4: Schema-Link Audit (D-03) — extension to existing script

Current `audit_cross_app_links.py` checks **(a) target table exists in DB**. D-03 adds **(b) target DocType's `module` ∈ UNIVERSITY_MODULES**. Patch:

```python
def _validate_d03(target_doctype, dt_to_app, dt_to_module):
    """Two-condition check per D-03."""
    # Condition (a): exists
    if not frappe.db.exists("DocType", target_doctype):
        return "BROKEN", f"Target DocType '{target_doctype}' does not exist"
    # Condition (b): module ownership
    target_module = dt_to_module.get(target_doctype) or frappe.db.get_value(
        "DocType", target_doctype, "module"
    )
    if target_module not in UNIVERSITY_MODULES:
        # ERPNext/HRMS/Frappe core links are LEGITIMATE cross-app -- only flag if it's Education
        if target_module == "Education":
            return "BROKEN", f"Target '{target_doctype}' is owned by deprecated Education module"
        return "EXTERNAL_OK", f"Target '{target_doctype}' in non-univ module '{target_module}'"
    return "PASS", ""
```

**Disk vs DB scan tradeoff:**
- `audit_cross_app_links.py` already scans **disk JSON** (`os.walk` over `apps/*/doctype/*/*.json`) to build the doctype-to-app map. Keep this — it catches dead/orphaned doctype JSON files that DB metadata wouldn't show.
- **For module ownership check**, query DB (`tabDocType.module`) — the JSON file's `module` field can drift from DB after manual edits. DB is source of truth.

## Common Pitfalls

### Pitfall 1: Card Break label vs card_name mismatch
**What goes wrong:** Workspace consistency check passes when comparing labels, but Desk renders blank because `Workspace.content` blocks reference `card_name` which is the slugified label.
**How to avoid:** In the consistency check, normalize both sides — check whether `link.label == content_block.data.card_name` OR `frappe.scrub(link.label) == content_block.data.card_name`. Use exact match first; if zero matches, fall back to scrubbed.

### Pitfall 2: Workflow walker pollutes DB
**What goes wrong:** Submitted test docs (workflows that move to `docstatus=1`) cannot be deleted normally. `frappe.delete_doc("X", name)` silently fails.
**How to avoid:** Use `frappe.delete_doc(doctype, name, force=1, ignore_permissions=True)` in the `finally` block. Confirm row deleted via `frappe.db.exists`. Wrap whole walker in `frappe.db.savepoint("wf_test")` + rollback for absolute safety.

### Pitfall 3: Schema-link audit catches ERPNext/HRMS as "broken"
**What goes wrong:** D-03 says "module ∈ university_erp" — but Faculty Profile.employee → HRMS Employee is a LEGITIMATE cross-app link. Flagging it = noise.
**How to avoid:** Three-state result: `PASS` (target in univ modules), `EXTERNAL_OK` (target in ERPNext/HRMS/Frappe core), `BROKEN` (target in Education or missing). Only `BROKEN` blocks the phase gate. See Pattern 4 above.

### Pitfall 4: Dynamic Link false positives
**What goes wrong:** Audit walks Dynamic Link fields and tries to verify the `options` (companion field name) as if it were a target DocType.
**How to avoid:** Existing `audit_cross_app_links.py:_discover_cross_app_links` correctly distinguishes — it puts `Dynamic Link` fields in a separate `dynamic_links` list and queries the **companion field's distinct values** at runtime to find actual targets. Preserve this logic; do not regress to single-list handling.

### Pitfall 5: Re-seed against pre-3.3.1 fixtures
**What goes wrong:** If any fixture under `university_erp/fixtures/` still references `education.education.doctype.X.X`, the post-clean re-seed will fail at fixture-load.
**How to avoid:** Before running `seed_all`, grep `frappe-bench/apps/university_erp/university_erp/fixtures/` for `"education.education"` substring. Phase 03.3.1-06 should have eliminated all such references (per its summary), but verify defensively.

### Pitfall 6: Wipe order regression when adding new doctypes
**What goes wrong:** Future doctypes added without entry in `clean_all`'s lists will accumulate stale rows across re-seed cycles.
**How to avoid:** After plan 01 re-seed, run a quick count: `frappe.db.sql("SELECT COUNT(*) FROM tabX")` for every doctype in the 7 ex-Education modules. Any non-zero count + missing from `clean_all` → add.

### Pitfall 7: `frappe.has_permission` returns True for has_permission_method overrides
**What goes wrong:** Permission probe shows a role can read X, but custom `has_permission` hook denies at runtime.
**How to avoid:** For doctypes with a `has_permission` hook (check `hooks.py:has_permission` dict), supplement the probe with an actual `frappe.get_doc(dt, name)` attempt under `frappe.set_user`. Catch `frappe.PermissionError`. Pattern is already in `audit_permissions.py:_test_api_endpoint`.

def check_link_field_d03(source_dt, fieldname, target_dt):
