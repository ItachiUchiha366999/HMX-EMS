# Phase 03.3.1 Plan 06: Education Fork Finalization Summary

## One-liner

Migrated all 7 Education hooks + after_install logic into university_erp, forked education.api/utils helpers inline, ran bench migrate cleanly, verified all 62 forked doctypes are owned by their destination module in the DB, and applied the School House -> 'Hostel House' / Education Settings -> 'Academics Settings' relabels via Property Setters -- Education app remains installed (per user directive) but is no longer referenced by any university_erp code path.

## What Was Built

### 1. hooks.py migration (Task 1)

Appended Education's hooks to `university_erp/hooks.py`:

- `accounting_dimension_doctypes = ["Fee Schedule", "Fee Structure", "Fees"]`
- `website_generators = ["Student Admission"]`
- `treeviews = ["Assessment Group"]`
- `calendars = ["Course Schedule"]`
- `default_roles = [{"role": "Student", "doctype": "Student", "email_field": "student_email_id"}]`
- `standard_portal_menu_items` -- /fees + /admissions
- `website_route_rules` -- appended `/admissions -> Student Admission`
- `global_search_doctypes = {"University ERP": [...31 forked doctypes...]}` (quiz/article entries dropped since archived in Plan 02)
- Dropped `"education"` from `required_apps` (now `["frappe", "erpnext", "hrms"]`)
- Extended fixtures filter so the two Education-fork Property Setters export cleanly.

### 2. install.py migration (Task 1)

Appended idempotent functions to `university_erp/setup/install.py` and wired them into `after_install()`:

- `setup_education_fixtures()` -- creates Party Type "Student" (Receivable) if absent
- `create_parent_assessment_group()` -- creates root Assessment Group "All Assessment Groups" if absent
- `create_student_role()` -- creates Role "Student" (desk_access=0) if absent

Education's 6 `patches.txt` entries were NOT copied -- they have already executed against the live site and are now baked into the data; new sites get equivalent state via these `after_install` hooks.

### 3. Tightened import-integrity test (Task 2)

`tests/test_education_import_integrity.py` previously matched ANY occurrence of `from education.` -- including docstrings and string literals inside the fork/verify scripts themselves. Tightened the regex to `^\s*(?:from\s+education(?:\.|\s)|import\s+education(?:\.|\s|$))` (true import statements only) and added an explicit exempt list for `scripts/fork_education_module.py` and `scripts/verify_education_removable.py` whose string literals legitimately describe the patterns being detected. Now GREEN.

`verify_education_removable.py` continues to report 0 violations.

### 4. Forked education.api -> university_erp/api.py (Task 3)

Wave 2's fork-script rewrote `from education.education.<x>` -> `from university_erp.<x>` across all forked files. That left 4 sites pointing at `from university_erp.api import ...` (a file that did not exist), causing `bench migrate` to crash with ImportError on `Course Scheduling Tool`, `Program Enrollment Tool`, etc.

Fork target: `frappe-bench/apps/university_erp/university_erp/api.py` -- a verbatim copy of `frappe-bench/apps/education/education/education/api.py` with zero `from education.` imports. Re-export targets:

- `get_fee_components`, `enroll_student`, `get_student_group_students` (consumed by forked Program Enrollment Tool, Student Attendance, Program Enrollment, Student Monthly Attendance Sheet report).

### 5. Migrated Education utils symbols (Task 3)

Appended to `university_erp/utils.py`:

- `class OverlapError(frappe.ValidationError)` -- consumed by forked Course Scheduling Tool
- `validate_overlap_for` + `get_overlap_for` -- consumed by forked Assessment Plan, Course Schedule
- `validate_duplicate_student` -- consumed by forked Student Group
- `check_content_completion`, `check_quiz_completion` -- consumed by forked Student doctype

Quiz/LMS helpers (`get_or_create_course_enrollment`, `enroll_in_program`, etc.) were intentionally NOT migrated since their consumers (Quiz/Question/Quiz Activity) are quarantined to `_archived/` and never registered with Frappe.

### 6. Inlined helpers into Assessment Result (Task 3)

`get_assessment_details` + `get_grade` (originally `education.education.api`) inlined into `university_academics/doctype/assessment_result/assessment_result.py` next to the only consumer. Matches the Plan 05 pattern for `validate_student_belongs_to_group`. The forked file's `from university_erp.api import get_assessment_details, get_grade` import was dropped.
